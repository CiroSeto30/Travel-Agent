# feat/database — Piano di implementazione

> **Per chi esegue:** segui i task in ordine; ogni passo ha una casella (`- [ ]`) da spuntare. Ogni task termina con test verdi e un commit.

**Obiettivo:** modelli del database, catalogo sintetico deterministico e script che crea le tabelle e carica il catalogo in PostgreSQL.

**Architettura:** SQLAlchemy 2 (stile dichiarativo tipizzato) con psycopg 3. Le tabelle si creano con `Base.metadata.create_all` (niente migrazioni: fuori perimetro per la scadenza). Il catalogo nasce da file JSON scritti a mano più dati generati (voli, disponibilità) con un seme casuale fisso. I test girano su un database separato, `travel_test`, nello stesso container Postgres.

**Stack:** Python 3.12+, SQLAlchemy 2.0, psycopg 3, pytest.

**Spec:** `docs/design.md` (§5 Modello dati, §6 Catalogo sintetico, §14 Test).

## Vincoli globali

- Importi: `NUMERIC(10,2)` nel database, `Decimal` in Python, mai float.
- Categorie attività: `culture`, `food`, `nature`, `sport`, `relax`, `nightlife`.
- Target attività: `families`, `young`, `couples`, `sporty`.
- Stati itinerario: `proposed`, `superseded`, `booked`, `cancelled`. Stati prenotazione: `confirmed`, `cancelled`.
- Tipi di voce itinerario: `flight_out`, `flight_return`, `hotel_night`, `activity`; esattamente una tra `flight_id`, `hotel_id`, `activity_id` valorizzata.
- Hotel da 2 a 5 stelle.
- Aeroporti di partenza: NAP, FCO, MXP. Destinazioni: 11 paesi (Giappone, Spagna, Grecia, Portogallo, Francia, Islanda, Regno Unito, Paesi Bassi, Thailandia, Stati Uniti, Italia), 3 città ciascuno (33 città), un aeroporto per città. Le città italiane di destinazione non coincidono con quelle di partenza (per esempio Firenze, Venezia, Palermo).
- Catalogo: 200 hotel (6 o 7 per città) e 500 attività (15 o 16 per città).
- Catalogo per i 12 mesi (365 giorni) a partire dalla data del seed; seme casuale fisso `42`.
- Tutti i comandi si lanciano dalla cartella `backend/` con l'ambiente virtuale attivo e i container accesi.

## Punti di attenzione per la revisione

1. **Seed lanciato due volte:** non deve duplicare dati né fallire. → test in Task 6.
2. **Database di test mancante:** i test devono crearlo da soli al primo avvio, senza passi manuali. → Task 1.
3. **Dati JSON incoerenti** (hotel in una città senza aeroporto, categoria scritta male): il seed deve fallire con un messaggio chiaro, non caricare dati sporchi. → test in Task 4.
4. **Prezzi con decimali:** un prezzo generato come `123.456` deve arrivare nel database come `123.46`, non come float approssimato. → test in Task 5.
5. **Isolamento dei test:** un test non deve vedere i dati scritti da un altro. → fixture con rollback in Task 1, verificata in Task 2.

### Task 5: Generazione deterministica di voli e disponibilità

**File:**
- Crea: `backend/seed/build_catalog.py`
- Test: `backend/tests/test_build_catalog.py`

**Interfacce:**
- Consuma: `BaseData` dal Task 4.
- Produce: `build_catalog(base: BaseData, start: date, days: int = 365, seed: int = 42) -> Catalog`; `Catalog` è una dataclass con liste di dict pronte per l'inserimento: `flights`, `hotel_availability` (con `hotel_index` al posto dell'id), `activity_slots` (con `activity_index`). Funzione di supporto `season_factor(d: date) -> Decimal`.

Regole di generazione (fissate qui, non a discrezione):
- **Stagionalità** (`season_factor`): luglio–agosto `1.40`; dicembre `1.30`; aprile–giugno e settembre `1.10`; altri mesi `0.90`.
- **Voli:** per ogni coppia (partenza, destinazione), in entrambe le direzioni, un volo al giorno tranne il martedì. Prezzo = `base_fare × season_factor × (1.10 se venerdì, sabato o domenica, altrimenti 1.00) × variazione casuale uniforme tra 0.85 e 1.15`, arrotondato a 2 decimali con `ROUND_HALF_UP`. Orario di partenza casuale tra 06:00 e 20:00 a passi di 15 minuti; arrivo = partenza + `flight_hours`. `seats_left = 20`.
- **Hotel:** una riga per notte per ogni hotel. Prezzo = `base_price × season_factor × variazione tra 0.90 e 1.10`, arrotondato come sopra. `rooms_left = 5`.
- **Attività:** una riga per ogni giorno il cui giorno della settimana è in `weekdays`. `spots_left = 10`.
- Un solo `random.Random(seed)`, usato nell'ordine: voli, hotel. Stesso input → stesso output.

    a, b = build_catalog(BASE, START, days=30), build_catalog(BASE, START, days=30)
    assert a.flights == b.flights and a.hotel_availability == b.hotel_availability
